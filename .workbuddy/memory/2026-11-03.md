## 登录页左侧品牌区重构

**问题**：原左侧用 `justify-between` 三段式布局，在 900px/1080px 高屏上内容分别贴住左上与底部，中间大片空白；且内容 `max-w-md` 靠左，1920 下右侧留白过大，视觉上「缩在左边和下边」。

**方案**：改为「AI 生成的公寓夜景插画 + 渐变遮罩」的品牌视觉，并重排信息层级。

- 背景图：`public/images/login-bg.jpg`（1024×1450，236KB）。由 ImageGen 生成的深蓝夜景公寓插画，原始 PNG 右下角带生成水印，用 PIL 裁掉底部 86px 后转 JPG，并做提亮 1.14 / 对比 1.04 / 饱和 1.06。
- 通过 `next/image` + `fill` 铺满左栏，`object-[50%_46%]` 取景；上覆两层渐变（100° 左深右浅 + 底部压暗）+ `grid-bg` 网格，保证白字可读、右侧建筑轮廓可见。
- 结构：`mx-auto max-w-[36rem] flex flex-col`（水平居中，不再贴左）→ 顶部品牌行 / 中部 `my-auto` 主视觉 / 底部运营数据卡。中部垂直居中解决上下贴边问题。
- 功能特性由裸列表改为 `divide-y` 玻璃卡片（`bg-white/[0.055]` + `backdrop-blur`），与底部数据卡同宽对齐；数据卡改为 3 列玻璃卡片。
- 移动端（<lg）新增 208px 顶部品牌图带（`object-[50%_64%]` 取景建筑、渐隐到白），logo 白色 lockup 绝对定位于图上，表单整体 `pt-20`，避免手机端只剩一张白板表单。

**验证**：1440/1920/1280/390 四档截图走查；`tsc --noEmit` 0 错误、构建通过、控制台无报错、登录接口 200。

## 路由切换卡顿排查与修复

**测量方法**：playwright-core 驱动本机 Edge，记录「点击 → 目标内容出现」的耗时、long task、RSC 请求耗时；再用 curl 带 `RSC: 1` 头单测各路由 TTFB。

**实测数据（修复前）**
- 各路由服务端 TTFB（预热）：60–135ms；冷路由 550–680ms（`/contracts` 546ms、`/tenants` 680ms）。
- 点击 → 内容出现：81ms（工作台）/ 105ms（账单）/ 118ms（报表）/ 158ms（房间）；RSC 请求本身仅 14–47ms。
- 无 long task，说明不是客户端 JS 卡住，而是**导航空窗期**。

**根因**
1. `src/app` 下**没有任何 loading.tsx**。App Router 的导航要等服务端 RSC 到齐才切页，没有 loading 边界时点击后只能停在旧页面 → 表现为「点了没反应，然后突然换页」。
2. 所有页面 `export const dynamic = 'force-dynamic'` 且依赖 cookie，Next 15 对动态路由默认不预取完整内容（仅在有 loading 边界时预取骨架），于是每次点击都要付一次完整 SSR。
3. Next 15 默认 `staleTimes.dynamic = 0`，返回/重复切换都重新请求。

**修复**
- 新增 `src/app/(app)/loading.tsx` 骨架屏（4 张指标卡 + 列表行），并在 `globals.css` 加 `.skeleton` 与 shimmer 动画（`bg-slate-200/80`，白 65% 扫光；初版 `slate-100` 太淡看不见）。
- `next.config.js` 加 `experimental.staleTimes = { dynamic: 30, static: 300 }`。
- 新增 `src/components/layout/nav-link.tsx`：`<Link prefetch>` 全量预取 + `useLinkStatus()` 导航中把图标换成转圈，给出即时反馈；`app-shell` 的 8 个导航项与「系统设置」改用它。

**效果**
- 悬停后点击 → 内容出现：**22–30ms**（原 81–158ms）；无悬停冷点击 59ms。
- 点击瞬间 URL 与侧边栏高亮立即更新，导航中图标转圈。

**备注**：`useLinkStatus` 仅能在 `<Link>` 内部子组件中使用（本实现放在 NavIcon 里）。

## 18:10 导航二次优化：冷路由归零 + 去掉菜单 loading

**用户反馈**：上一版仍不够流畅，尤其冷路由首访；希望「主框架不变、只换内容」；菜单上不要 loading。

**根因（这次查实）**
1. `.next` 里没有 BUILD_ID，且 3000 端口上同时跑着 `next dev -p 3000`（PID 3956）和一个 `next start`。开发服务会不断重写 `.next`——这才是之前反复出现 `Cannot find module './xxx.js'` / 全站 500 的元凶，也让「冷路由 550–900ms」成立（dev 按需编译）。
2. `prefetch` 实际一次都没发生：抓 `_rsc` 请求，挂载后 3s 内 0 条预取，每次点击都是全新 RSC（`Next-Router-Prefetch` 头缺失）。Next 15 对 `force-dynamic`（读 cookie）页面默认不做完整预取。
3. 路由级 `loading.tsx` 几乎没有反馈价值：导航走 React transition，RSC 未就绪时 React 保留旧页面，采样显示 0–1.5s 内 skeleton 数为 0，直到数据到达才闪一下骨架再出内容 —— 就是「点了没反应，然后抖一下」。

**改动**
- 新增 `layout/route-preloader.tsx`：首屏稳定后 `requestIdleCallback` 逐个 `router.prefetch()` 全部 9 条路由（90ms 间隔）。点击时 RSC 请求数从 1 → **0**。
- 删除 `src/app/(app)/loading.tsx`；新增 `layout/navigation-progress.tsx`：顶栏下 2px 进度条，**100ms 后才显示**（缓存命中不出现），点击捕获 `document` 上的内部链接，pathname 变化即收起，4s 兜底。
- `nav-link.tsx` 去掉 `useLinkStatus` 转圈，只保留高亮切换（用户明确要求）。
- `layout/route-transition.tsx`：`key={pathname}` 的内容容器 + `animate-fade-in`，切换时内容淡入。
- `globals.css`：`html { scrollbar-gutter: stable; overflow-y: scroll }`，`main` 加 `min-h-[calc(100vh-4rem)]` —— 消除内容高度变化引起的滚动条抖动（内容区宽度实测切换前后都是 1196px）。
- `next.config.js`：`distDir = dev ? '.next-dev' : '.next'`，`staleTimes.dynamic` 30 → 60。**dev 不再污染生产构建产物**，两者可同时运行（已验证：dev 起在 3100，`.next/BUILD_ID` 保持完好）。

**效果**（Edge headless，1440×900，生产模式）
- 冷路由首访：219–910ms → **59–109ms**（点 8 个菜单全部 0 次 RSC 请求）
- 回访：73–126ms → **49–60ms**
- 慢导航（RSC 人为延迟 1.4s）：旧内容保持不动，272ms 时进度条出现，无骨架闪烁；侧边栏 boundingBox 切换前后完全一致
- `tsc --noEmit` 0 错误；`smoke.mjs` 27/27 通过；控制台零报错；数据重置为 60 房 / 44 租客 / 44 合同 / 174 账单 / 11 工单

**教训**：排查「卡顿」先确认 `next start` 还是 `next dev` 在服务、`.next` 里有 BUILD_ID、浏览器是否真的发了预取请求，再谈优化。
